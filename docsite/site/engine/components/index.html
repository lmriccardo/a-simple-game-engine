Components

An entity in ASGE is just an id; its components are the data that gives it behaviour. These are all the components the engine ships. Each is plain data, saved to a scene as a TOML table of the same name, and acted on by a system. Mix them freely: a sprite that animates and collides is an entity with a Transform, Sprite, Animator and Collider.

New to the model? Read Entity-Component-System first. Add components in the level editor or from code through the Registry.

Core components

These describe an entity's identity and place in the world. Almost every scene entity carries a Transform.

Name · Transform · Hierarchy · Disabled

Rendering and animation components

What gets drawn, in what order, and from where.

Sprite · RenderInfo · Camera · Animator

Physics components

Collision shapes and motion. See the Physics theory page for how they are used.

Collider · Rigidbody · Velocity

Audio components

Sound playback. See the Audio theory page.

AudioSource

Path components

A route and a follower are two entities. The Path lives on the route entity; the follower is its child and finds the Path through its parent, so the scene file needs no entity references. Authoring: Make an entity follow a path.

Path · PathFollow

UI components

A UI widget is an ordinary entity: a UIRect footprint plus the components for what it does. Build them with the asge::game::ui::Create* functions rather than by hand. See the UI theory page and Arrange the UI.

UIRect · Interactable · UIButton · UILabel · UICheckbox · UISlider · UIProgressBar · UIPanel · UILayoutItem · UIDebugOverlay
