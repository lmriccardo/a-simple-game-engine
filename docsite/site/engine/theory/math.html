Math

The small maths toolbox the rest of the engine leans on: vectors, shapes, collision tests and interpolation.

The concept

2D games are mostly vectors and rectangles. Keeping them in one dependency-free module, rather than reaching into SDL types, means gameplay, physics, rendering and the editor all speak the same small set of types.

How ASGE does it

Linear algebra

asge::math::Vec2<T> (and Vec3), built on a shared VecN, with the common aliases Float2, Double2, Int2 and Int642. Arithmetic operators are provided; positions, sizes and mouse deltas throughout the API are Float2 or Int2.

Geometry and collision

Rect and Circle are the two collider shapes. Collision.hpp has the overlap tests (AabbOverlap, CircleOverlap) and PenetrationVector overloads for every rect/circle pairing, returning an std::optional<Float2> that says how to push the first shape out of the second. Physics is built on these.

Interpolation

  • Easing and Ease(easing, t): Linear, InQuad, OutQuad, InOutQuad, OutCubic; the input is clamped to [0, 1].
  • Tween<T>: moves a float, Float2 or similar from one value to another over a duration; call Update(dt) each frame and read Value().
  • CatmullRomSpline: a smooth curve through waypoints, with arc-length sampling so motion along it is at constant speed. PathFollowingSystem and the editor's path preview use it.
math.cpp
using asge::math::Easing;

asge::math::Tween<float> slide( 0.0f, 100.0f, /* seconds */ 2.0f, Easing::OutQuad );

// each frame:
slide.Update( dt );
float x = slide.Value();       // eased value; slide.IsFinished() once the duration has elapsed
