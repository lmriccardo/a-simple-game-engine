Assets

Loading an image or a sound is slow; loading it twice is wasteful. An asset layer loads each file once and shares it.

The concept

Assets (textures, fonts, audio, animation data) are loaded by name and cached, so the second request for the same asset is a lookup. Components then hold a cheap reference or a path instead of a copy, and a scene file can store just the path.

How ASGE does it

AssetManager and AssetPool

asset::AssetManager is the one entry point. It is built over a VirtualFileSystem and owns a path-keyed AssetPool per asset type, each a cache of std::shared_ptr<Asset<T>>:

  • GetImage, GetAudio, GetFrameTable by virtual path; GetFont by path and pixel height, since a font is baked at a size.
  • GetTexture uploads an image to the GPU once, caches the ITexture by virtual path and keeps ownership; UnloadTexture drops it.
  • Loads fail with a Result error when the path does not resolve through the VFS or the file cannot be decoded.
assets.cpp
asge::game::asset::AssetManager assets( vfs );

auto image = assets.GetImage( "textures/hero.png" );   // Result<shared_ptr<Asset<Image>>>
auto again = assets.GetImage( "textures/hero.png" );   // cached: same asset, no second decode

Resolving components

A Sprite stores its m_VirtualPath and m_SourceRect; those are what round-trip through a scene file. Each frame ResolveAssets (called from Game::Render) turns the paths of sprites and animations back into live textures. A sprite's texture therefore points into the manager's cache and must not outlive it.

Spritesheets and animation clips

A FrameTable is a named sequence of source rects into a spritesheet, loaded from a small TOML file. A GridSpec describes a contiguous range of cells over a regular grid (row-major or column-major), and MakeGridFrames does the grid math. An optional frame_durations array gives frames their own display time.
