UI & Layout

Build HUDs and menus without writing TOML: create buttons, labels, checkboxes, sliders and panels from the Entities panel, drop them into a panel, and let the panel's layout place and size them. Everything is assembled through the same ui::Create* functions a game uses, so what you see here is what a game gets.

Create UI Element

The Create UI Element button in the Entities panel (disabled until a project is open, like Create Entity) opens a two-step flow: pick a type, then fill in its details.

Button

Name, position, size, enabled flag, and Color / Hover / Pressed colors, with optional caption text.

Label

Text, font, size, alignment and color. Auto Size fits the rect to the text; turn it off to give the label a fixed size.

Checkbox

Box colors, the check color, and whether it starts checked.

Slider

Min, Max and starting Value, the track color, and the thumb's Color / Hover / Pressed colors.

Panel

A background container: background and border colors, margin, padding, spacing, and a layout for its children.

Every type also takes a Name, a Position and a Screen Space flag (on by default -- HUD elements stay put as the viewport pans and zooms). Fonts are picked from the ones loaded in the Assets panel, not typed as a path. Back returns to the type list, Discard closes without creating.

Once created, each widget's components get their own Inspector sections (UIRect, Interactable, UIButton, UILabel, UICheckbox, UISlider, UIPanel) for viewing and editing. They have no x: a widget is a bundle of components, so you delete the whole entity instead of one piece of it.

Panel Parent

Every creation form ends with a Panel Parent section: a dropdown of the panels already in the scene, with (none) selected by default. Pick one and the new widget is created as that panel's child, so the panel lays it out from the next frame on. A panel can be the parent of another panel, which is how you nest layouts.

An entity can also be moved into a panel later: drag its row onto the panel in the Entities tree (see Entities & Components).

Panel layouts

A panel's Layout decides where its children go. The editor applies it live, so children snap into place in the viewport the moment they are attached.

LayoutOptionsBehavior
Absolute—Children keep whatever position and size they have.
GridRows, ColumnsEqual cells, filled row by row in sibling order.
VStackRowsEqual-height rows, each as wide as the panel, top to bottom.
HStackColumnsEqual-width columns, each as tall as the panel, left to right.

Slots are laid out inside the panel's rect, inset by its Margin and Padding on every side, with Spacing left between neighboring slots. A child takes the next slot in sibling order (the order shown in the Entities tree), and only children that have a Transform count. Children past the last slot keep their own position.

Per-child options: UILayoutItem

By default a child stretches to fill its slot on both axes. When you need a checkbox to stay square, or a slider to span the width but keep its height, add a UILayoutItem to that child from the Inspector's Add Component list.

FieldWhat it does
Fill X / Fill YStretch the child to the slot on that axis. Off keeps the child's own size there.
Align X / Align YWhere an axis that doesn't fill sits in the slot: Start, Center or End.

Sprites are drawn at their texture's size and auto-sized labels fit their own text, so neither is ever stretched, even with Fill on. They can still be aligned.

Good to know

The layout wins

A child of a Grid/VStack/HStack panel has its position (and size, unless a UILayoutItem says otherwise) recomputed every frame, so dragging it or editing its Transform won't stick. Edit the panel, or set the panel to Absolute.

Duplicate keeps the layout

Duplicating a child puts the copy in the same panel, as its next slot. Duplicating a panel copies it together with everything inside it.

Not interactive here

The editor only draws UI. Buttons, checkboxes and sliders don't react to clicks or dragging until you run them in a game.

Panels sit behind

New panels are drawn on a layer behind ordinary widgets, so what you put inside one stays visible on top of it.
