# Scripting & Events — Phase 3

*Priority: Well past MVP — a real embedding + binding story is a substantial
undertaking. See [README](../README.md). Other phases:
[Phase 2](../phase-2/11.2-scripting-and-events.md) (event bus, native scripting).*

## Goals
Managed (non-C++) scripting for gameplay logic, and hot-reloading scripts at
runtime without restarting the game.

## Design notes
- **Language choice is an open question, not a foregone conclusion.** Lua is the
  traditional lightweight embed for a C++ engine; C#/Python bindings are heavier
  undertakings with their own build/packaging cost. This phase should evaluate
  against actual authoring needs once
  [Phase 2](../phase-2/11.2-scripting-and-events.md)'s native `Script` component
  is in real use and its limitations are concrete, not decide the language
  speculatively now.
- **Runtime reload** depends on whatever embedding is chosen supporting it cleanly
  — some script VMs make this straightforward, others don't; a real constraint on
  the language choice above, not an independent task.
