# Physics System — Phase 2

*Priority: Tier 2 follow-on. See [README](../README.md). Other phases:
[Phase 1](../phase-1/07.1-physics-system.md) (AABB, gravity, collision response),
[Phase 3](../phase-3/07.3-physics-system.md) (soft body, vehicle physics).*

## Goals
Fast-moving entities that don't tunnel through thin colliders, a way to query the
world without a physical entity (raycasts), and a purpose-built controller for the
most common gameplay archetype (a player character).

## Design notes
- **Continuous collision detection (CCD)** only matters once
  [Phase 1](../phase-1/07.1-physics-system.md)'s discrete per-frame AABB check
  actually produces visible tunneling — fast projectiles or thin walls. Not worth
  building preemptively.
- **Character controller** is a special-cased, non-physical movement mode (the
  player doesn't tumble like a ragdoll) built on top of Phase 1's collision
  detection, not full rigid-body dynamics — most 2D platformers/top-down games want
  this over "the player is just another `Rigidbody`".

## Tasks
- [ ] Continuous collision detection for fast-moving `Rigidbody` entities
- [ ] Raycast query API against the `Collider` set, independent of `Rigidbody`
- [ ] Character controller: slope/step handling, grounded checks, built on
      Phase 1's `Collider`

## Deliverables
- A raycast API usable from gameplay code without spawning an entity
- A character controller at least one example uses for player movement instead of
  raw `Rigidbody` velocity

## Explicitly out of scope
Soft body and vehicle physics — see [Phase 3](../phase-3/07.3-physics-system.md).
