# Rendering System (2D) — Phase 2

*Priority: Gated — may never trigger. See [README](../README.md).
Other phases: [Phase 1](../phase-1/10.1-rendering-system.md) (camera, fixed-function effects).*

## Goals
A programmable-shader path, but only if a real feature ever needs one. This whole
phase is one decision gate followed by three steps that only happen if the gate
opens — unlike every other system's Phase 2/3, which are "do this later", this one
may permanently stay at "not done, and that's fine".

## Design notes
`SDLRenderer` stays the primary backend unless this phase explicitly decides to
replace or supplement it — nothing here happens by default. The four
sub-steps below are strictly sequential and each blocks the next; there's no
parallel work to pull forward.

## Tasks

### Step 1 — Decision gate

Not a build task — a checkpoint. Revisit `SDL_GPU` only once a concrete feature
(lighting, particles, a specific visual effect) actually needs custom shading logic
that [Phase 1](../phase-1/10.1-rendering-system.md)'s fixed-function tricks can't cover. If
nothing ever needs it, Steps 2-4 below stay skipped indefinitely; that's a valid
outcome, not a stalled roadmap item.

- [ ] Identify a concrete feature that fixed-function compositing can't cover

### Step 2 — `SDL_GPU` backend spike

- [ ] Stand up a second `IRenderer`-conformant backend (`SDLGPURenderer`) against
      SDL3's `SDL_GPU` API, alongside `SDLRenderer`, not replacing it
- [ ] Minimum bar: clear + one textured quad + one custom shader effect, ideally
      headless-testable the same way `SDLRenderer` is
- [ ] Shaders precompiled per-backend (SPIR-V/DXIL/MSL) via `SDL_shadercross`
- [ ] Exit decision: dual-backend permanently (`SDLRenderer` for everyday drawing,
      `SDL_GPU` only for the effect that triggered this), or full swap, or the
      spike reveals it isn't worth it and Step 1's gate stays closed

### Step 3 — Shader system

Only after Step 2 lands. A minimal way to attach a compiled shader + uniforms to a
draw call through `IRenderer`, scoped to whatever triggered Step 1 — not a general
shader authoring pipeline.

- [ ] Shader + uniform attachment on `IRenderer` draw calls

### Step 4 — Material system

Shader + parameters + texture bindings as a reusable object, wired into
`DrawTexture`/`DrawString`-equivalent calls. Only worth doing once Step 3 has more
than one consumer.

- [ ] Material object composing shader + params + texture bindings

## Deliverables
- A written decision (in this doc) on whether/when `SDL_GPU` was adopted, and why —
  even "the gate never opened" is a valid, documented outcome

## Explicitly out of scope
Everything here is gated behind Step 1; none of it is scheduled independently.
