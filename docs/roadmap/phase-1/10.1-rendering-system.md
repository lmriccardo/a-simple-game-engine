# Rendering System (2D) — Phase 1

*Priority: Tier 3 — revisit once Tier 1-2 exist and something demands it.
See [README](../README.md). Other phases: [Phase 2](../phase-2/10.2-rendering-system.md)
(`SDL_GPU` decision gate, shaders, materials).*

## Goals
Camera control, layer-ordered draw submission, sprite/frame animation, and
fixed-function compositing effects (tint, glow, fade) on top of the 2D
primitives from [02-Rendering Primitives](02.1-rendering-primitives.md) — the
MVP-appropriate slice of "rendering system", with zero backend risk since
it's built entirely on `SDLRenderer`'s existing render-target/color-mod/
blend-mode support. Not a 3D pipeline: no mesh renderer, no PBR, no ray
tracing.

## Current state
Layer-based draw ordering and sprite/frame animation are done (see Tasks
below). Camera control and compositing effects are not started, and remain
deprioritized behind [03-ECS](03.1-entity-component-system.md) and
[04-Input](04.1-input-system.md) — an MVP needs entities and input before it
needs camera zoom or a glow effect.

## Design notes
`SDLRenderer` stays the primary backend throughout this phase; nothing here
replaces it. Compositing effects (tint, additive glow, fade) reuse
`SDL_Renderer`'s existing render-target + color-mod + blend-mode support instead of
needing shader work — proving out several "shader-ish" effects before
[Phase 2](../phase-2/10.2-rendering-system.md) even asks whether real shaders are worth it.

Layer ordering is submission-order sorting, not a render-target/compositing
concern: `RenderSystem` collects one `DrawItem` per drawable `(Transform, Sprite)`
pair, sorts the batch by `Sprite::m_Layer` first, then — only where either item
opts into `Sprite::m_YSort` — by the sprite's bottom-edge Y (painter's algorithm
for 2D depth within a layer), then by entity index for a stable order among ties,
and draws in that order. No z-buffer, no separate render passes per layer — a
single `SDL_Renderer` pass with sorted submission is enough for a 2D engine.

Sprite/frame animation is state-machine driven. An `asset::AnimationStateMachine`
(a `.animsm` XML file) declares flags, triggers, clip names, states and the
transitions between them; an `asset::AnimationClipSet` (a `.animset` XML file)
binds each clip name to a frame table and a frame duration. A
`components::Animator` names a clip set and plays it: game code only sets flags
(`SetFlag`) and fires triggers (`Fire`), and the machine's transitions pick the
state. `systems::AnimatorSystem` advances it and writes the current frame
straight into the owning entity's `Sprite::m_SourceRect` — no separate "animated
sprite" draw path, `RenderSystem` just sees whatever source rect the animator
last wrote. `systems::RenderPipeline` sequences `AnimatorSystem`, `CameraSystem`
then `RenderSystem` for callers that want all three without wiring them up
themselves. Only the clip set path, playback speed and start-playing flag
round-trip through `Serializer<Animator>` — state, frame, flags and triggers are
runtime state, not something a scene file describes.

A clip can face several directions. Instead of a `path`, a `<Clip>` of the clip
set holds 1 to 8 `<Variant path>` children, one frame table per direction,
spread evenly clockwise from north (4 variants are N/E/S/W, 8 add the
diagonals; other counts divide the circle equally). All variants share the
clip's `frameDuration`; a clip with a `path` attribute is a single variant and
ignores direction. `Animator::m_Heading` (a screen-space vector, south until
set, never serialized) picks the variant: `AnimatorSystem` takes the nearest
direction with `math::QuantizeAngle`, with a small hysteresis so a heading on a
boundary does not flicker, and a heading change swaps the frame table without
restarting the clip, keeping the frame. The system also feeds the heading
itself: a moving `PathFollow` supplies its path tangent, otherwise a nonzero
`Velocity` its direction, otherwise the last heading stays, so an entity that
stops keeps facing the way it moved. A game can set it directly with
`components::SetHeading`.

```xml
<AnimClipSet machine="anim/humanoid.animsm">
  <Clip name="run" frameDuration="0.10">
    <Variant path="anim/hero_run_n.toml"/>
    <Variant path="anim/hero_run_e.toml"/>
    <Variant path="anim/hero_run_s.toml"/>
    <Variant path="anim/hero_run_w.toml"/>
  </Clip>
  <Clip name="death" path="anim/hero_death.toml" frameDuration="0.10"/>
</AnimClipSet>
```

## Tasks
- [x] Layer-based draw ordering: `Sprite::m_Layer` (explicit draw-order bucket) +
      `Sprite::m_YSort` (optional per-sprite opt-in to sort by vertical position
      within a layer, for top-down/isometric depth); `RenderSystem` sorts a
      `DrawItem` batch before submitting draw calls
- [x] Sprite/frame animation: `components::Animator` + `systems::AnimatorSystem`
      play an `AnimationStateMachine` through an `AnimationClipSet` and write the
      current frame into `Sprite::m_SourceRect` each frame
- [x] Directional clips: up to 8 `<Variant>` frame tables per clip, chosen from
      `Animator::m_Heading` (set by `SetHeading`, or taken from a moving
      `PathFollow` or `Velocity`)
- [x] 2D camera (position, zoom, rotation applied to `DrawX` calls)
- [ ] Render-target compositing helpers (tint, additive glow, fade) on the existing
      `SDL_Renderer` backend — no shader work required

## Deliverables
- `Sprite::m_Layer` / `Sprite::m_YSort` + a sorting `RenderSystem` (done)
- `components::Animator` + `AnimationStateMachine` + `AnimationClipSet` +
  `systems::AnimatorSystem`/`RenderPipeline` (done)
- `IRenderer` extended with camera-aware draw calls
- Compositing helper API for tint/glow/fade built on the current backend

## Explicitly out of scope for Phase 1
`SDL_GPU`, shaders, materials — see [Phase 2](../phase-2/10.2-rendering-system.md). Mesh
renderer, material/lighting systems scoped for 3D, PBR, GPU instancing of meshes,
deferred rendering/shadows/HDR, ray tracing, global illumination — these are
3D-pipeline concerns carried over from an earlier generic template and don't apply
to a 2D SDL engine; revisit only if the engine's scope changes.
