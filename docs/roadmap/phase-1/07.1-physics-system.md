# Physics System — Phase 1

*Priority: Tier 2 — first system that makes gameplay feel like gameplay.
See [README](../README.md). Other phases:
[Phase 2](../phase-2/07.2-physics-system.md) (CCD, raycasts, character controller),
[Phase 3](../phase-3/07.3-physics-system.md) (soft body, vehicle physics).*

## Goals
Basic 2D collision and gravity — enough that entities can bump into each other and
fall, without a general-purpose 2D physics engine.

## Current state
Collision detection and response exist and are tested, and gravity is wired
up. `math::AabbOverlap`/`math::PenetrationVector`
([Core/Math/Geometry/Rect.hpp](../../../src/ASGE/Core/Math/Geometry/Rect.hpp))
do the AABB overlap test and minimum-translation-vector calculation.
`Rigidbody` ([Game/Components/Rigidbody.hpp](../../../src/ASGE/Game/Components/Rigidbody.hpp))
now exists — `m_Mass` plus an `m_AffectedByGravity` flag — as the
physics-driven marker `03-ECS`'s component catalog anticipated, orthogonal to
the pre-existing `Velocity` component rather than replacing it.
`systems::CollisionResolution` ([Game/Systems/PhysicsSystem.cpp](../../../src/ASGE/Game/Systems/PhysicsSystem.cpp))
applies the MTV as an all-pairs check over every `Transform`+`Collider`
entity: an entity only counts as movable if it has both `Velocity` and
`Rigidbody` (anything missing either — e.g. static level geometry — is
immovable), and when both overlapping entities are movable the correction is
split by mass ratio (the heavier body yields less) rather than evenly.
Zeroing velocity on whichever axis was corrected is unchanged.
`systems::GravitySystem` (new, same file) adds a constant acceleration to
`m_DY` each frame for every `Rigidbody`+`Velocity` entity whose
`m_AffectedByGravity` is true. `systems::MovementSystem` (plain
velocity-integration) is unchanged. `examples/physics_demo` demonstrates all
of it together — a static floor/walls, a falling/settling stack of
mass-varied boxes, click-to-spawn, reset.

Not done yet: a single `PhysicsSystem()` entry point wiring gravity +
movement + collision together — a caller (currently `physics_demo`) still
calls `GravitySystem`, `MovementSystem`, and `CollisionResolution` separately,
in the right order, by hand.

## Design notes
- **AABB only, not arbitrary shapes.** Matches this engine's 2D scope
  ([00-overview](../00-overview.md)) — axis-aligned bounding boxes cover the common
  2D gameplay case (platformers, top-down) without the complexity of a general
  narrowphase for rotated/convex shapes.
- **A system, not a class hierarchy.** Following [03-ECS](03.1-entity-component-system.md)'s
  own convention: a `PhysicsSystem` is a plain function operating on a view of
  `Transform`+`Collider`+`Rigidbody`, the same shape as the existing
  `MovementSystem`/`RenderSystem`, not a `Rigidbody` base class with virtual methods.
- **Gravity as a constant force applied to the existing `Velocity` component**,
  not a second velocity field on `Rigidbody` — `Rigidbody` turned out to need
  only `m_Mass` and `m_AffectedByGravity`; duplicating `Velocity` inside it
  would have meant keeping two velocities in sync for no benefit.
  `GravitySystem` integrates into `Velocity.m_DY`, and `MovementSystem`
  already integrates `Velocity` into `Transform.m_Position` — reusing that
  step rather than building a second one.

## Tasks
- [x] AABB collision detection (`Collider` vs `Collider`, from
      [03-ECS](03.1-entity-component-system.md)'s existing component) —
      `math::AabbOverlap`/`math::PenetrationVector`
- [x] Gravity: constant acceleration applied to a `Rigidbody`+`Velocity`
      entity's `Velocity.m_DY` each frame — `systems::GravitySystem`
- [x] Collision response: basic resolution (stop/push out on overlap, split
      by mass ratio when both sides are movable) — not full impulse-based
      rigid body dynamics — `systems::CollisionResolution`
- [ ] `PhysicsSystem` as a plain function, following `MovementSystem`'s existing shape
      — `MovementSystem`/`GravitySystem`/`CollisionResolution` exist as three
      separate plain functions; nothing wires them into one `PhysicsSystem()`
      call yet

## Deliverables
- `PhysicsSystem` detecting AABB overlaps between entities with `Collider` —
  detection + response exist (`CollisionResolution`), not yet exposed as one
  `PhysicsSystem` symbol
- Gravity affecting any entity with `Rigidbody` — done (`systems::GravitySystem`)
- At least one example demonstrating a falling/colliding entity — done
  (`examples/physics_demo`)

## Explicitly out of scope for Phase 1
Continuous collision detection, raycasts, character controller
([Phase 2](../phase-2/07.2-physics-system.md)); soft body and vehicle physics
([Phase 3](../phase-3/07.3-physics-system.md)); broadphase beyond a naive all-pairs
check (revisit only if [13-Optimization](13.1-optimization.md) profiling shows it's
needed — no entity count in this engine justifies it yet).
